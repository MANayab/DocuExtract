## 1. OCR

### Verified behavior

- OCR is implemented as an optional build-time feature: `src/config/build.ts` exposes `OCR_BUNDLED`; `src/content/site.ts` changes the user-facing claim depending on whether OCR assets were bundled.
- `docs/OCR.md` documents the pipeline: pdf.js renders each page to a canvas at `OCR_RENDER_SCALE=3` (~216 dpi), Tesseract recognizes it in a Web Worker, and recognized words become positioned text spans for the normal extractor. OCR-origin fields are marked source `ocr`, confidence is capped at 75%, and OCR always requires review.
- Same-origin/local-only design is documented in `docs/OCR.md` and `PRIVACY.md`; `index.html` CSP has `connect-src 'self'`, `worker-src 'self' blob:`, and no remote origins. `scripts/prepare-ocr-assets.mjs` is documented as copying the worker, WASM core and English trained data into the site's own `public/ocr/`. This supports the intended local-only architecture, but a live browser Network-tab check was **NOT RUN** in this audit.
- Limits in `src/config/limits.ts`: 25 MiB per PDF, 100 pages general maximum, 20 pages for OCR, 50 PDFs per batch, OCR render scale 3, and 24,000,000 pixels per OCR canvas. `src/utils/fileValidation.ts::validatePdfFile` enforces file size and PDF extension/MIME checks.
- `docs/OCR.md` explicitly says handwriting, photos taken at an angle and low-resolution faxes are not reliable; it does not document rotation correction or deskew.

## 2. Multi-invoice splitting

### Verified behavior

- `CHANGELOG.md` v1.1.0 says splitting occurs where the invoice number changes and multi-page invoices stay together; it also calls out changing invoice number as a limitation.
- `src/features/batch/batchStore.ts::run` turns each returned invoice into a separate record with segment index/total. `sourceFileFor` and `reprocessWithLocale` map split IDs such as `f1#2` back to the original PDF and select the matching invoice by segment index.
- `src/tests/unit/batchStore.test.ts` tests expansion of three returned invoices into three records and that the segment is marked. This test exercises store mapping, **not the underlying PDF boundary detector**.

### Failure-mode matrix

| Scenario | Status | Evidence |
|---|---|---|
| Boundary uses invoice-number changes | **VERIFIED** | `CHANGELOG.md` v1.1.0; implementation parser source was not conclusively located through the repository integration. |

| “Page 2 of 3” continuation | **UNVERIFIED** | No direct implementation/test evidence inspected. |
| Repeated headers | **UNVERIFIED** | No direct implementation/test evidence inspected. |
| Missing invoice number | **UNVERIFIED** | No boundary-level test inspected. |
| Two invoices with same number | **VERIFIED LIMITATION RISK** | Number-change splitting is documented; equal-number adjacent invoices may not create a boundary. No test inspected. |
| Credit notes | **UNVERIFIED** | No direct evidence inspected. |
| Line items/totals leaking across boundary | **UNVERIFIED / HIGH RISK** | No boundary-level test fixture inspected. |
| Totals before items | **UNVERIFIED** | No direct evidence inspected. |

**Implementation decision:** Do not replace or redesign the splitter until its source and failure modes can be inspected and reproduced. The integration did not provide a repository tree or useful code-search matches; claiming a splitter fix now would be speculative.

## 5. Privacy and security

- **No application upload path is documented:** `PRIVACY.md` states that PDFs are processed locally and not sent to a server, analytics or telemetry. This is an architecture/documentation claim, not a live Network-tab observation.
- **CSP is present:** `index.html` limits default/script/connect/font/image sources to self (plus explicit data/blob and worker allowances) and disables objects; `connect-src 'self'` is restrictive. CSP effectiveness in the deployed browser was **NOT RUN**.
- **No invoice persistence is documented:** `PRIVACY.md` and README say no localStorage/sessionStorage/URL persistence; OCR uses `cacheMethod: 'none'` per `docs/OCR.md`. Runtime storage inspection was **NOT RUN**.
- **Limits:** 25 MiB per file, 100 pages general, 20 pages OCR, 50 files per batch, 24M pixels per OCR canvas (`src/config/limits.ts`). `validatePdfFile` checks type/name and size. Malformed, encrypted, decompression-bomb and oversized-page handling were not exhaustively tested.
- **Encrypted/password PDFs:** no explicit verified handling path was found in inspected sources; mark **UNVERIFIED**.
- **Local OCR assets:** docs say worker/WASM/language assets are served from this origin, not CDN. Confirmed by configuration/docs, not network capture.

## Scope decision for v1.3.0

Only the stale JSON export version is a directly verified, bounded implementation defect from the source inspected so far. OCR rotation/deskew is a documented limitation, but the recognition implementation was not located well enough to safely change. Multi-invoice boundary handling is explicitly not to be rewritten without inspecting and reproducing the splitter. The v1.3.0 PR must not claim those unverified items are fixed.
