## 3. OCR language vs invoice locale

**NOT A GAP (conceptual separation already exists); OCR selection is a VERIFIED GAP.**

- Invoice locale options are defined in `src/config/locales.ts`: `en-IN`, `en-US`, `en-GB`, `de-DE`. `src/app/App.tsx` controls the locale and passes it to parsing/reprocessing via `src/features/pipeline/processPdf.ts`.
- OCR language is currently fixed in the generated OCR manifest and passed to Tesseract by `src/features/ocr/ocrEngine.ts`. It is not read from the invoice locale state.
- Do not derive OCR language from the locale selector. They answer different questions: OCR language identifies the script/language in the scan; invoice locale determines interpretation of ambiguous dates and numeric separators.

## 5. Privacy, CSP and licenses

- **NOT A GAP (source policy):** `index.html` sets `connect-src 'self'`; worker policy is `worker-src 'self' blob:`; `script-src` includes `wasm-unsafe-eval` for WASM. Tesseract worker/core/language paths are derived from `import.meta.env.BASE_URL` in `ocrAssetBase()`.
- **UNVERIFIED (runtime):** source inspection cannot prove no document content appears in any network request. Human must inspect DevTools Network during upload and OCR and confirm requests are limited to app-origin static assets, with no invoice payload.
- **NOT A GAP (existing documentation):** `PRIVACY.md` states OCR files are same-origin and not cached in browser storage; `docs/OCR.md` describes `cacheMethod: 'none'` and the Network check.
- **VERIFIED GAP for multi-language release:** `docs/THIRD-PARTY-LICENSES.md` lists `@tesseract.js-data/eng`, but must list every additional traineddata package/model and exact license/source before bundling it.
- No backend, analytics or telemetry should be added. CSP must remain restrictive; do not introduce external OCR/CDN origins.

2. **UNVERIFIED:** perform and record a live Network-tab privacy check during OCR; source-only inspection is insufficient.
3. **VERIFIED GAP:** test that OCR output remains marked for review and capped at 75 confidence for every supported language.

### P1 — broken or untested feature
1. **VERIFIED GAP:** implement an OCR language selector, separate from invoice locale, with English default and clear distinction.
2. **VERIFIED GAP:** support multiple language assets in `scripts/prepare-ocr-assets.mjs` and manifest; add language-model failure handling and retry.
3. **VERIFIED GAP:** add language loading, language selection, non-English extraction/review and locale-independence tests.
4. **VERIFIED GAP:** test OCR worker termination/canvas cleanup on success and failure; provide cancellation if the current UI supports safe cancellation.
5. **VERIFIED GAP:** cover export parity after a manual edit in XLSX, invoice CSV, line-item CSV and JSON.
6. **VERIFIED GAP:** test mixed text/scanned PDFs and rotated scans; do not claim rotation/deskew until verified.
7. **VERIFIED GAP:** update license notices and docs for each bundled language model.

4. **P2:** audit hero contrast and overlap at 320, 375, 768, 1024 and 1440 CSS px; automated geometry test added, but its result is NOT RUN until branch CI concludes.

## Proposed v1.4.0 language set

Start with **English (`eng`), Hindi (`hin`) and German (`deu`)**. English remains the default. This is a deliberately small set covering the current English-first app, a major Indian language, and the locale parser's German numeric convention. It does not imply universal language support or accuracy. Validate actual package/model availability, license terms, and compressed sizes before implementation. If package availability or redistribution licensing cannot be verified, do not bundle that model until resolved.
