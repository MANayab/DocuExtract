## 3. OCR language and pipeline

### Central configuration and language handoff

- `ocr-languages.json` is the shared language list used by the Node asset script and TypeScript UI.
- `src/features/ocr/ocrLanguages.ts` provides the typed `OcrLanguage` union, option shape and default `eng`.
- The list contains English (`eng`), Hindi (`hin`) and German (`deu`), with native labels, file names and size notes.
- `src/app/App.tsx` stores OCR language independently from invoice locale and renders options from the central list.
- `src/features/batch/batchStore.ts` stores the selected OCR language and passes it to the processor.
- `src/features/pipeline/processPdf.ts` forwards it to `ocrPdf`.
- `src/features/ocr/ocrEngine.ts` validates the selected language against the manifest and calls `createWorker(language, ...)`. There is no silent fallback.

### Model source, license and measured bytes

Pinned wrappers: `@tesseract.js-data/eng@1.0.0`, `@tesseract.js-data/hin@1.0.0`, `@tesseract.js-data/deu@1.0.0`. The npm wrappers declare MIT. The underlying `4.0.0_best_int` traineddata is from `naptha/tessdata` and is Apache-2.0. Both MIT and Apache license text plus attribution are copied to `public/ocr/licenses/` by the asset build.

### Same-origin and lazy network behavior

- `scripts/prepare-ocr-assets.mjs` copies the worker, core, configured models and license texts to `public/ocr/`; missing models or notices fail the build.
- `src/features/ocr/ocrManifest.ts` uses `import.meta.env.BASE_URL + 'ocr'`.
- `src/features/ocr/ocrEngine.ts` sets worker, core and language paths under that same-origin base, with `workerBlobURL: false` and `cacheMethod: 'none'`.
- The app no longer fetches the manifest on initial load. The manifest, worker, WASM and selected language file are requested only after OCR is requested; text-only extraction does not invoke the OCR engine.
- CSP in `index.html` continues to restrict network requests to self and allows the required worker/WASM behavior. Live Network-tab confirmation remains **NOT VERIFIED**.

### Mixed pages, cleanup, progress, cancellation and recovery

- `src/features/pdf/pdfTextExtractor.ts` classifies the document as image-only only when all page text layers are empty.
- `src/features/pipeline/processPdf.ts` finds pages with no extractable text, requests OCR only for those page numbers, and merges their OCR text/spans with existing text pages in original page order.
- `src/features/ocr/ocrEngine.ts` applies the 20-page OCR limit to pages selected for OCR, caps each canvas at 24 million pixels, releases each canvas and page in per-page `finally`, and terminates the worker and destroys the PDF in outer cleanup.
- Progress callbacks include page number and page count.
- AbortSignal is checked before/after recognition and between pages. The current page may finish; the worker is then terminated and resources released.
- `BatchStore` tracks cancellation, retains the file record, and allows retry after cancellation or OCR errors. The UI exposes Cancel OCR and Retry OCR.
- Failed manifest fetches are not cached permanently. Model load failures include the selected language and memory guidance; no fallback language is chosen.
- OCR-derived invoices pass through `markAsOcr`, which marks values as OCR and caps confidence at 75.

### Limits

- Maximum 20 pages requiring OCR per PDF; mixed PDFs may have additional text-layer pages.
- Maximum canvas area 24,000,000 pixels; maximum render scale 3.
- Shared PDF validation: 25 MiB and 100 total pages.
- No wall-clock OCR timeout; cancellation stops between pages.
- Locale parsing, GST calculations, validation rules and export contracts were not intentionally changed.

## 4. Invoice locale independence and UI

Invoice locale remains `LocaleCode` from `src/config/locales.ts`; OCR language is `OcrLanguage` from the central OCR configuration. They are separate React state and separate processor options. The batch-store regression test checks that changing one does not change the other.

The UI now has distinct groups titled “Invoice locale (dates and numbers)” and “Scanned PDF language (OCR)”, each with a visible label, select and helper text. The OCR helper says it applies only to scanned/image-only pages and results need review. CSS keeps label/select in one row on wide screens and stacks them at narrow widths, with visible focus styling and high-contrast text. Playwright covers 320, 375, 768, 1024 and 1440 px; the current run is pending.
